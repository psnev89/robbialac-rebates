# Project verification

- Install dependencies: `python3 -m pip install -r requirements.txt`.
- Run the app: `python3 -m streamlit run app.py`.
- Run regression tests: `python3 -m unittest -v`.
- Check syntax: `python3 -m compileall -q app.py rebates.py catalog_editor.py persistence.py`.
- Keep financial rules in `rebates.py`; `catalog_editor.py` adapts the community AG Grid component to Streamlit; `persistence.py` commits the catalog to GitHub through the Contents API. `paint_jobs.py` extracts painting work items from a "Caderno de Encargos" PDF via an LLM for the "Trabalhos de pintura" tab.
- Paint-jobs extraction supports Google Gemini, Anthropic Claude and OpenAI (provider + model dropdowns in the tab). Each provider reads its key from app secrets or env vars (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`), like `GITHUB_TOKEN`. The uploader accepts multiple PDFs at once (e.g. Caderno de Encargos + Mapa de Quantidades); all documents go into a single LLM request so quantities can be cross-referenced. Gemini uploads them via the Files API then deletes them; Claude and OpenAI send the files as base64. All providers return the same parsed DataFrame. Results stay in session state keyed by uploaded file; reruns and table edits never repeat the LLM call. The tab renders the PDF beside an editable table whose "Exportar" checkbox picks which rows reach the Excel download; the "Área selecionada" metric sums the m² quantities of selected rows.
- Catalog persistence on Streamlit Cloud: the "Gravar catálogo" button commits `static/catalogo.xlsx` via the GitHub API (the filesystem is ephemeral — never write app state to the checkout, it can break future `git pull`s). Configure a fine-grained PAT with `Contents: read & write` as `GITHUB_TOKEN` in app secrets (optionally `GITHUB_REPO`/`GITHUB_BRANCH`); `.streamlit/secrets.toml` is gitignored and env vars work as a fallback. The push triggers a redeploy that reloads the new file.
- Browser checks should cover repeated edits after scrolling, sorting/searching then editing by stable row ID, filtered selections, pinned new-product rows, per-product rate edits, per-product rebate VAT checkboxes, single/bulk offer imports, and catalogue exports. Unit tests do not verify grid JavaScript.
- Catalog search and sorting are view-only: rebates and exports always use the full catalog. Search ignores case and accents; changing it clears selections and select-all targets filtered rows only.
- If Rerun does not pick up an imported module change, restart Streamlit. Export session catalog edits first and reimport afterwards; restarting loses session state.
- Catalog product gross price (`preco`), shipping (`portes`) and per-product VAT percentage are authoritative. Editing a rate preserves the gross price; net price, VAT amount and `preco_total` (preco + portes) are derived. Missing rates default to 23% and should be reviewed by the user. On import, a "Preço total" column is treated as including portes (product price = total − portes); "Preço c/ IVA" columns are read directly.
- Each catalog row has a "Usar preço c/ IVA" checkbox (`usar_iva`): checked uses product gross + portes, unchecked uses product net + portes; multiply the selected unit cost by quantity. Shipping always counts and carries no VAT split. Toggling it must never mutate prices or rates. Products missing the flag are initialized once from the legacy limit rule (gross > limit → checked).
- App palettes live in `.streamlit/config.toml`; the catalogue grid derives its colors from the active Streamlit theme. Verify both Light and Dark through the top-right main menu when changing styles.
- `streamlit-aggrid==1.2.1.post2` clears its grid theme during theme changes. The grid's `rowDataUpdated` listener restores the configured theme; its parameters reference Streamlit's live color variables to avoid stale `st.context.theme` values.
